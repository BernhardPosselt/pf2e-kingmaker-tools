# Random Encounter & Rumor Curator — UI/Template Changes Spec

**Feature:** Random Encounter & Rumor Curator (roadmap item #11)
**Parents:** Research summary (task t_301b62d2), Data model spec (task t_e6434cc3)
**Format:** Follows `docs/plans/quest-event-generator.md` conventions

---

## Overview

This spec covers all UI and template changes needed for the Random Encounter & Rumor Curator feature. It builds on top of the data model spec from the parent task, which defines 5 new types (`EncounterCategory`, `CategoryWeights`, `Rumor`, `MerchantStock`, `QuestTemplateReference`), extensions to 3 existing models (`CampingData +5`, `RegionSetting +2`, `KingdomData +1`), and `Migration27`.

### Architecture Summary

The curator extends the existing random encounter flow with a category-based routing system. Instead of a single proxy table deciding "Creature vs. nothing," a category proxy table routes to category-specific tables (Combat, RP, Rumor, Merchant, Disease, Faction, Weather, Lore). A new `EncounterPreviewDialog` (GM-only, following the `ConfirmWatchApplication` pattern) lets the GM preview, accept, reject, or reroll encounters before they are posted to chat. Rumors generated by encounters can be converted into quests (`QuestTemplateReference` stored in `KingdomData.rumorGeneratedQuestIds`).

### Design Decisions Applicable

- **Decision 2** (GM-only default): Encounter preview dialog is GM-only by default
- **Decision 4** (hex state): Actor (kingdom) is source of truth for hex state filtering
- **Decision 6** (explored+cleared sync): Suppresses COMBAT encounters in claimed+cleared hexes

**Action handlers:**
- `accept-encounter`: Posts the result to chat using the appropriate chat message template (`random-camping-encounter.hbs` for combat, `curated-rumor.hbs` for rumors, etc.), updates `CampingData.lastEncounter`, saves, closes.
- `reroll-encounter`: Re-rolls the category proxy table and the category-specific table, re-renders the dialog with new result.
- `reject-encounter`: Discards result, closes dialog, no chat output.
- `convert-rumor-quest`: Triggers `AddQuest` dialog pre-populated with rumor quest hook data. Sets `KingdomData.rumorGeneratedQuestIds` with the new quest ID.

### 4e. RandomEncounters.kt Changes

**File:** `src/jsMain/kotlin/at/posselt/pfrpg2e/camping/RandomEncounters.kt`

The core rolling logic needs to:

1. Roll the `encounterCategoryProxyTableUuid` table to determine the category.
2. Roll the category-specific table (from `RegionSetting.categoryRollTableUuids[category]`) for the actual result.
3. Apply hex state filtering: if `filterByHexState == true` and hex is claimed+cleared and category == COMBAT, suppress (return false/no result).
4. Store result in transient `lastEncounterCategory` / `lastEncounterResult` on CampingData.
5. Open `EncounterPreviewDialog` for GM preview instead of directly posting to chat.

**Hex state filtering logic:**

```kotlin
fun CampingData.isCombatSuppressed(kingdomData: KingdomData): Boolean {
    if (!filterByHexState) return false
    if (currentRegion == null) return false
    // Check if current region's hex is claimed and cleared in kingdom data
    val currentHex = kingdomData.getHexForRegion(currentRegion)
    return currentHex?.claimed == true && currentHex?.cleared == true
}
```
